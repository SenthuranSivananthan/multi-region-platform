Azure Key Vault across regions

Data can be recoverable while the application cannot start without its keys, secrets, and certificates. Key Vault is multi-tenant; Managed HSM is single-tenant.

Paired regions

Eligible Standard/Premium vaults replicate asynchronously to a Microsoft-managed copy. Microsoft may take hours or longer to initiate failover; afterward access is read-only. Private Link reconnection can add 20 minutes.

Microsoft-managed failover exclusions

Microsoft-managed failover is not supported for non-paired regions, regions with asymmetric pairing or paired regions across two different geographies. Use independent vaults or supported Managed HSM replication. See failover eligibility and security worlds.

Common key-management scenarios

Application encryption
Match application operations; preserve identifiers and versions.

Azure Storage - Geo-redundant storage (GRS)
One account/key dependency. Independent vaults do not assign separate keys to GRS replicas.

Azure Storage - Object replication for block blobs
Separate accounts can use independent keys and vaults.

VM disk encryption
Regional Disk Encryption Sets; distinguish guest encryption and Secure Key Release.

Azure Site Recovery
Pre-create target-region Disk Encryption Set and vault access. Do not infer HSM support.

PostgreSQL / MySQL Flexible
Replica, geo-backup, and geo-restore have different key, region, and identity rules.

Azure SQL Database, Azure SQL Managed Instance and Azure Cosmos DB geo-replication
SQL permits documented regional key copies; Cosmos DB has account-level CMK requirements.

Azure SQL Database, Azure SQL Managed Instance and Azure Cosmos DB geo-restore
Retain historical keys; validate target region, identities, and backup requirements.

Purview Information Protection
Identify tenant-key BYOK versus Customer Key. Preserve keys for old content.
